## Why

The group file tells the planners which group is the app by a key whose only job is to be found: `owns = "remainder"` on `[group.waypoints]`, which `remainder_group` in `tooling/xtask/src/release_groups.rs` searches for and `semver_check`, `src-tauri/build.rs`, `nix/channel.nix`, and the app recipe each re-derive in their own way. The same group carries `counts = "closure"`, which makes every commit that counts for any library count for the app too, and the remainder rule makes every path no library owns — `website/`, `docs/`, `nix/`, `.github/`, `openspec/`, `deploy/`, the root manifests — the app's work. So a docs-only pull request moves the app's version, a `bedrock` fix is a `waypoints` fix, and the first cut's app target is computed over the whole repository rather than over the app. Beside those two keys sit six more that nothing reads — `minted`, `floors`, `features-always-increment-minor`, `channels`, `flavors`, and the whole `[enforce]` table — declared by `release-groups-guards` so the file's shape would be settled once, and still waiting for a reader that never came because the code decided each policy from the kind of group instead. `breaking` is read, but only to learn what "is this the app" already says.

Decided with John on 2026-11-17: this is tooling for one repository and one app, not general-purpose build tooling, so the app's group is named in code and ownership is written down rather than inferred. `release_groups.rs` names the app group `waypoints`, beside `workspace::APP`, which already names the app's crate; a group owns its `members`, `internals`, `fixtures` directory, and a new `paths` list of directories, and a path no group lists counts for no group; the closure goes, so a library commit counts for its library alone; a cut whose cycle holds no app work refuses rather than compute a target below the last stable release; and every key whose only reader was the policy its kind already implies goes with the schema regenerated. This continues `group-file-versions`' D2, which removed `anchor` for the same reason — a key nothing reads drifts into meaning something — and finds the app's crate by name.

Why now: the first cut has not run. `group-file-versions` landed on 2026-11-17 and folded `library-minting`'s run-time audits into its last task group, which the first cut performs. Under the closure, that cut would measure the app over every commit in the repository and the dry run John reads before it would describe a target the app's own paths may not justify. Landing this first means the first cut measures the app over the app, and the dry run he audits says what the app's paths say.

## What Changes

- **The app group is named.** `release_groups.rs` gains a constant naming the app group `waypoints`, and `load` refuses a file without `[group.waypoints]`. The `owns` and `counts` keys, the `Owns` and `Counts` enums, `remainder_group`, `closure_groups`, and the key-based `app_group()` go. Every reader that tells the app from a library does so by the name: the planners, `semver_check::library_members` and the `semver` task, `src-tauri/build.rs`, `nix/channel.nix`, and the app recipe's `group-versions`.
- **Ownership is explicit; attribution stays by changed path.** A group owns its `members`, `internals`, `fixtures` directory, and the directories its new `paths` key lists, matched as directory prefixes the way `test::owning_package` already matches. `waypoints` lists `src/`, the Tauri app's Nuxt frontend. A path no group lists counts for no group, so `website/`, `docs/`, `nix/`, `.github/`, `openspec/`, and the root manifests stop counting for the app; `tooling/` and the `[bookkeeping]` paths count for none, as now. `deploy/`, the Station's Kubernetes manifests, is proposed for `outpost`'s `paths` and left for John to decide (design.md, Open Questions). The planner refuses a listed path that does not exist, sits under `tooling/`, or overlaps another group's.
- **The closure goes.** `history::attribute` stops adding the closure groups to every counted commit: a commit counts for exactly the groups whose owned paths it changes. The app's version moves on app-owned paths only; the app adopting a library change is an `app` or `cartograph` commit, and a series taking a newer library is a pin move landed by `patch`. Nightlies keep building `main` from source, and the group versions a build embeds already record what each nightly shipped. The fixture floor on the app is unchanged: a changed fixture under any group still floors the app's cut, because that floor reads the diff since the last stable, not the attribution.
- **A cut with nothing counted for the app refuses.** With the closure gone a cycle can hold library work and no app work; `cut_target` would then compute a target from no headers, which `Version::cut` turns into a prerelease of the last stable release itself. The planner refuses first, naming the last stable tag (or that none exists), the library groups that did move, and `release-plan cut --group <name>` as the way to mint one alone, in the style of the `--group` refusal that already exists. The message lives in `templates.toml`.
- **Policy follows from the kind, so the unread keys go.** `minted`, `floors`, `features-always-increment-minor`, `channels`, `flavors`, and `[enforce]` are deleted from the parser, the file, and every fixture; `breaking` is deleted and `header_for` derives the rule from whether the group is the app. The schema is regenerated with `cargo xtask release-groups schema`; a file still carrying any of them does not parse, as a misspelled key does not. The group file's header comments stop naming `breaking` and `minted`.
- **The first dry cut is re-read.** After this lands, `cargo xtask release-plan cut --dry-run` is run again and John reads the app's target and each group's counted commits against the first-parent history. Today it prints `0.1.0-pre.1` with `main` moving to `0.2.0-nightly`, measured over every commit.

## Capabilities

This change stays inside the `distribution` domain: which paths a group owns, what a commit counts for, and when a cut refuses are release planning; what the summary rule reads as a group's own paths is release integrity. Nix delivery reads the same file but its published requirements already say "the version the group file declares for the app" without naming a key, so `distribution/nix-overlay` is not touched.

### New Capabilities

None.

### Modified Capabilities

- `distribution/release-planning`: three requirements are **ADDED** — _The app's group is named `waypoints`_, _A group owns only the paths the group file lists_, and _A cut with nothing counted for the app refuses_. One is **REMOVED**: `library-minting`'s _Groups own disjoint paths, and the app counts what it ships_, whose ownership half continues in the second ADDED requirement and whose closure half is withdrawn; that requirement is in `library-minting`'s open delta rather than the main spec, so this REMOVED applies once `library-minting` has archived, which design.md's Migration Plan states. `library-minting`'s _A multi-group commit is a summary_ has two scenarios that end "and for `waypoints`" or "a feature for `waypoints`"; they are superseded by _A group owns only the paths the group file lists_, and as `group-file-versions` did with the anchor sentence, `library-minting`'s delta is not edited: whichever of the two changes reaches the main spec second carries the reconciliation. `group-file-versions`' MODIFIED _Every workspace crate is named in the group file_ is not modified again; the `waypoints` requirement stands beside it.
- `distribution/version-integrity`: _Landing commits are conventional, and summaries are complete_ is **MODIFIED** — a group's own paths are now the ones the file lists, `paths` included, so a pull request changing `src/` and a library's crate is a summary — with every existing scenario kept and two added.

## Impact

- **Group file and schema:** `tooling/release-groups.toml` loses `owns`, `counts`, `breaking`, `minted`, `floors`, `features-always-increment-minor`, `channels`, `flavors`, and `[enforce]`, gains `paths = [ "src/" ]` on `waypoints` (and `deploy/` wherever John places it), and its header comments change; `tooling/schemas/release-groups.schema.json` is regenerated.
- **`tooling/xtask`:** `release_groups.rs` (the app-group constant, `load`, `Group` and `GroupFile`, the deleted enums, `owned_paths`, `owner_of`, `touched`, `problems`); `releases/history.rs` (`attribute`, `header_for`, the module doc, every test asserting `waypoints` on a library commit); `planners/release.rs` (`plan`'s refusal, `app_group`, the test helpers `library_commit` and `workspace_groups`, `SERIES_GROUPS`); `semver_check.rs` and `src/bin/xtask/tasks/semver_check.rs` (`is_app` by name); `templates.toml` (the refusal); the group-file fixtures in `release_groups.rs`, `version_integrity.rs`, `releases/index.rs`, `tests/version_write.rs`, and `tests/planners_refuse.rs`.
- **Build data and Nix:** `src-tauri/build.rs` skips the app group by name; `nix/channel.nix` reads `groups.waypoints.version`; `nix/packages/waypoints/package.nix` filters the libraries by name.
- **Docs:** `docs/CONTRIBUTING.md`'s _Landing a pull request_ gains one sentence saying a path the file lists for no group counts for no release. Its statement that the changed paths decide the group stays true. `nix/AGENTS.md` names none of the keys and is untouched.
- **Planner behavior:** the nightly planner's "did anything land" reads the same walk, so a day whose only commits touch unlisted paths publishes no nightly. The `version-integrity` summary rule, which already read only the groups' own paths, now sees `src/` as the app's: a pull request touching the frontend and a library lands as a `summary`.
- **Unchanged:** the enumeration rule (every workspace member outside `tooling/` is named exactly once, and no `tooling/` crate is), the bookkeeping rule, what a cut mints, how a series pins, `version_of` and the lockstep clause, the projection, and the dry run's rendering.

## Non-goals

- No change to the `version` values the group file declares. They are John's to set; he intends to lower them separately so the first manual cuts land versions that can be committed to `main`. This change edits no `version` line.
- No change to what a cut mints, how tags are minted, how a series pins, or what the dry run renders; those are `library-minting` and `group-file-versions`.
- No globs in `paths`: directory prefixes, as `owning_package` matches them.
- No pinning of library tags on `main`; nightlies build from source (design.md D3).
- No new policy for nightlies, previews, or stables, and no change to the fixture floor or the API floor.
- No re-reading of history and no retroactive edit to any landed message.
- No edit to `library-minting`'s or `group-file-versions`' artifacts.
