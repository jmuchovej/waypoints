## Why

Bedrock, Outpost, Domain, Transload, and Waypoints are meant to version independently, but only the app's version is ever planned: every library manifest still says `0.1.0`, nothing writes them, and `the_app_declares_its_own_version` in `tooling/xtask/src/workspace.rs` records the intent without a mechanism. The one planner that reads history (`cut`) treats every commit in the repository as a statement about the app, reads subjects only — so trailers and body footers are invisible — honours `!` as breaking, and runs with `features_always_increment_minor(true)`, which makes a feature and a break produce the same bump before 1.0. After v1 the same history would mint false majors, and a monorepo commit such as `feat(outpost)!: deployable Station` that also edits callers elsewhere would read as breaking for every group it touched.

Every channel also builds whatever its tree holds. A preview or stable series would build its libraries from its own `crates/`, so a series would ship whatever cherry-picks happened to touch a library, and a promotion would relabel a preview build rather than compile stable's own combination. The channels are meant to be alpha, beta, and production — nightly is where questionable code is allowed to go — and that only means something if each channel is its own build of released library versions.

Why now: no series has been cut under the current pipeline — the remote carries one nightly tag and no `v*.x` branch — so the first cut is also the first that could mint libraries, and there is no in-tree series to migrate. This is the last of four changes that replace one monolithic plan, and it depends on the other three. `release-groups-guards` lands the group file and the first `version-integrity` checks, so a summary that mints is known to be complete before it merges. `protected-branches` lands the rulesets and routes every bot write through a pull request, so a library tag can name a merge commit on `main`. `channel-flavors` makes each channel its own flavored build, so a pinned library compiles under the series' flavor and the API floor has a stable surface to measure. Nothing here is live until all three are.

## What Changes

- **Path attribution over first-parent history.** The single `git log` both planners read (`releases::index::product_commits`) becomes group-aware: it walks `main`'s first-parent history, one merge commit per pull request, and reads each commit's changed paths, subject, body headers, and `Covenant` trailer. Each group owns disjoint paths; a library counts commits touching its own paths; the app counts its own paths plus every group's, because the binary ships them. Bookkeeping — `nix/releases/`, commits listed in `.git-blame-ignore-revs`, and the release bot's `chore(release):` commits — counts toward no group.
- **Reading summaries.** A commit touching more than one group's paths is a `summary` whose body carries one conventional header per touched group — the format and its completeness gate are `release-groups-guards`'. Here, each group reads its own header and the subject counts for no group; a library header follows Cargo's 0.x right-shift.
- **Library minting, on `main` only.** `release-plan cut` computes every library group's next version under Cargo's 0.x right-shift, lands all of them in one summary commit on `main` through a botswain pull request, and — once the merge commit exists — tags each changed group at the merge commit and cuts the `v{minor}.x` branch from it, pinned to those tags. A cut may be scoped to one group, which mints a library alone with no branch and no app movement: that is how a library fix reaches an existing series, as a new tag on `main` the series' patch then pins. A library line that has since taken a break on `main` cannot be patched into a series; the way to ship that fix is a new cut. A group tag is a source ref, not a release: it matches no release or index trigger and is never recorded.
- **Each channel builds the library versions it pins.** On a series branch the library groups are git dependencies on their tags, not path dependencies on the branch's own `crates/`; `main` keeps building in-tree, so nightly is where library work meets the app first. The in-tree copies stay on a series for cherry-picks to apply against but leave the workspace, and a pull request against a series that touches library code is refused — a series takes library changes only by moving a pin. The repository is public, so a git dependency on one of its tags needs no credential; the Nix overlay still vendors the lockfile's git sources for its offline build.
- **The Station package follows the pin.** On a series ref the overlay's `outpost` package is built from the `outpost` tag the series pins, not from the inert in-tree copy, so what gets built — and cached to cachix — for a series is a released `outpost`; on `main` it builds in-tree as today.
- **App severity.** The app ignores `!`. Its only breaking signal is a `Covenant: break` trailer, and a cut targets a major for the app only when a person passes `--major`; a trailer since the last stable makes a cut without `--major` refuse and name the commits.
- **Evidence floors.** A group's bump is the greater of what its commits declare and what evidence shows: `cargo semver-checks` against each library group's last tag, measured under the stable flavor since that is the surface every series consumes, and the append-only covenant fixtures under `covenant/fixtures/<group>/` whose modification is breaking for the owning group and the app. A group with no tag yet has no baseline, so the API check skips it and says so rather than block every library pull request before the first cut.
- **Two more pull-request checks** join `version-integrity`: a series pull request never touches library code and every crate pins the same tag per group — both armed only on a series whose manifests carry pins, so a series cut before minting keeps taking library cherry-picks; and an undeclared API break fails.
- **Build data.** Each build embeds every group's version — on `main` described from the tree's tags, on a series read from the pin, or injected where the source carries neither — alongside `BuildInfo`, for the About surface, `--version`, and bug reports.

## Capabilities

This change stays inside the `distribution` domain. Planner-side invariants are release planning; the pull-request checks on pins and API breaks are release integrity, the front half of distribution, not toolchain reproducibility; what the overlay's Station package builds on a series is Nix delivery.

### New Capabilities

None. `distribution/version-integrity` is created, with its purpose, by `release-groups-guards`; this change adds to it.

### Modified Capabilities

- `distribution/release-planning`: gains `ADDED` planner-side invariants — groups own disjoint paths and the app counts what it ships, read over first-parent history; library versions are minted only by a cut, on `main`, with group-scoped cuts and the pin-or-new-cut rule for series; a multi-group commit is a summary; the app breaks only on a covenant trailer; evidence floors each group's bump, measured under the stable flavor; builds embed every group's version; each channel builds the library versions its branch pins. Nothing published is `MODIFIED` here: the two amendments protecting the branches requires — _A series branch carries only cherry-picks of `main`_ and _The manifest version names the channel_ — are `protected-branches`'. _Release refs are minted so their pushes are observable_ stays as published and is what makes the App token mandatory for the group tags.
- `distribution/version-integrity`: two `ADDED` requirements — a series branch takes library changes only by pin (which also holds every crate to one tag per group), and an undeclared API break fails the pull request.
- `distribution/nix-overlay`: one requirement is **MODIFIED** — _Flake overlay exposes desktop packages_ said the `outpost` package builds from the tree the flake is evaluated from; it now builds the `outpost` crate that tree resolves, which on a pinned series is the tag the series pins. Every existing scenario is kept and one is added. This is the third and last `MODIFIED` delta across the four changes, and the only one outside `protected-branches`.

Two further published specs constrain this change without being touched: `distribution/release-publishing` (a channel publishes only the tag that triggered it, and withdraws only a tag it minted itself — a group tag triggers nothing and is minted by no run) and `distribution/release-index` (an entry follows its tag, and series carry no index — a group tag is never an entry). `nix-overlay`'s _A series ref builds itself_ stays as published: a series builds from its own lockfiles and pins, which the pinned git sources now are.

## Impact

- **`tooling/xtask`:** `releases::index::product_commits` becomes the group-aware first-parent walk and its `fixture::Repo` test helper grows paths, bodies, and merges; `planners::release` gains per-group plans, group-scoped cuts with floors, `--major`, the two-phase cut that rewrites the series' library dependencies to tags and drops the library crates from its workspace, and a `patch` that moves pins or refuses when a line has broken, with the new flags on `src/bin/xtask/tasks/release_plan.rs` and the group tags minted through `tools/github.rs`'s existing `octocrab` `create_tag`; the `version-integrity` task gains the series-pin, single-pin, and API-break checks and its workflow a `semver` job; `workflows/release.rs` and `workflows/_jobs.rs` fetch tags and inject group versions; `typegen` registers the new build-data type so the TypeScript bindings stay generated.
- **Manifests:** on a series, the root `[workspace.dependencies]` entries for `bedrock*`, `outpost*`, `domain`, and `transload` move from `path` to `git` + `tag`, and those crates leave `[workspace].members` while staying on disk; `crates/bedrock`, `crates/domain`, and `crates/transload` gain the `#:tombi toml-version = "v1.0.0"` directive the Nix reader needs (`crates/outpost` and the root already carry it); `cargo-semver-checks` joins the pinned toolchain.
- **Build data:** `crates/cartograph/src/build_info.rs`, `src-tauri/build.rs`, `src-tauri/src/commands/meta.rs`, `src-tauri/src/bin/waypoints.rs`, and `nix/packages/waypoints/package.nix` (the overlay builds a fetched tag with no git metadata, so it injects the values, and on a series it must vendor the git dependencies the lockfile pins).
- **`nix/packages/outpost/package.nix` and `nix/overlay.nix`:** on a series ref the Station is built from the `outpost` tag the lockfile pins — the fetch-by-rev path the recipe's header already anticipates — and reads that tag's manifest for its version; on `main` the in-tree build is unchanged.
- **Release pipeline:** the cut becomes two-phase (open PR → merge → tag, branch, series PR); the nightly planner's history walk becomes first-parent too, since both planners share one walk, but its decision — did anything land — is unchanged.
- **Docs:** `docs/CONTRIBUTING.md` gains the rule that a series never takes library code directly, beside the `summary` and trailer entries `release-groups-guards` adds.

## Non-goals

- No crates.io publishing: `publish = false` stays.
- No channels for library groups; they have no installed population. A library's "release" is a tag on `main` that series pin.
- No library hotfix for a line that has since broken on `main`. The fix ships through a new cut; the planner says so rather than minting a tag that pulls a breaking change into a series.
- No covenant fixture coverage. The directories and the append-only rule are `release-groups-guards`'; this change applies the fixture floor at cut. A fixture per migration, payload type, ACL record, and envelope version is a follow-up change touching `bedrock`, `outpost`, and `store`.
- No versioning for components that do not ship yet; each becomes its own group when it does. The importer SDK and its plugins, which are in flight and not yet on `main`, must be named in the group file when they land, and every planner run refuses until they are.
- No change to nightly versions (`{target}-nightly.N+YYYY.MM.DD`) or to the app's four transitions.
- No re-linting of history. The planners read older first-parent commits as `next_version` does today, dropping non-conventional subjects.
- No second source of versions: no ledger file, no version in the group file. A series' pins are dependencies, not a version source.
- No credential plumbing for git dependencies; the repository is public.
- No release record or channel for `outpost` itself. A series' Station is a build of a pinned tag; the index-recorded, fetch-by-rev path stays the app's.
