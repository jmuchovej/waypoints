## Why

Bedrock, Outpost, Domain, Transload, and Waypoints are meant to version independently, but only the app's version is ever planned: every library manifest still says `0.1.0`, nothing writes them, and `the_app_declares_its_own_version` in `tooling/xtask/src/workspace.rs` records the intent without a mechanism. The one planner that reads history (`cut`) treats every commit in the repository as a statement about the app, reads subjects only — so trailers and body footers are invisible — honours `!` as breaking, and runs with `features_always_increment_minor(true)`, which makes a feature and a break produce the same bump before 1.0. After v1 the same history would mint false majors, and a monorepo commit such as `feat(outpost)!: deployable Station` that also edits callers elsewhere would read as breaking for every group it touched.

Every channel also builds whatever its tree holds. A preview or stable series would build its libraries from its own `crates/`, so a series would ship whatever cherry-picks happened to touch a library, and a promotion would relabel a preview build rather than compile stable's own combination. The channels are meant to be alpha, beta, and production — nightly is where questionable code is allowed to go — and that only means something if each channel is its own build of released library versions.

Why now: no series has been cut under the current pipeline — the remote carries one nightly tag and no `v*.x` branch — so the first cut is also the first that could mint libraries, and there is no in-tree series to migrate. This is the last of four changes that replace one monolithic plan, and the other three have landed. `release-groups-guards` (archived 2026-11-05) landed the group file and the first `version-integrity` checks, so a summary that mints is known to be complete before it merges. `protected-branches` (2026-11-11) landed the rulesets and routes every bot write through a pull request whose merge the planner's own run waits for and tags, so a library tag can name a merge commit on `main`. `channel-flavors` (2026-11-03) made each channel its own flavored build, so a pinned library compiles under the series' flavor and the API floor has a stable surface to measure. `release-dry-runs` (2026-11-16) followed and gave every transition a rehearsal that renders its writes and refs as an artifact; this change extends that rehearsal to the groups a cut mints.

## What Changes

- **Path attribution over first-parent history.** The single `git log` both planners read (`releases::index::product_commits`) becomes group-aware: it walks `main`'s first-parent history, one merge commit per pull request, and reads each commit's changed paths, subject, body headers, and `Covenant` trailer. Each group owns disjoint paths; a library counts commits touching its own paths; the app counts its own paths plus every group's, because the binary ships them. Bookkeeping — `distribution/nix/releases/`, commits listed in `.git-blame-ignore-revs`, and the release bot's `chore(release):` commits — counts toward no group.
- **Reading summaries.** A commit touching more than one group's paths is a `summary` whose body carries one conventional header per touched group — the format and its completeness gate are `release-groups-guards`'. Here, each group reads its own header and the subject counts for no group; a library header follows Cargo's 0.x right-shift.
- **Library minting, on `main` only.** `release bump` computes every library group's next version under Cargo's 0.x right-shift, lands all of them in one summary commit on `main` through a botswain pull request, and — once the merge commit exists — tags each changed group at the merge commit and cuts the `v{minor}.x` branch from it. A cut may be scoped to one group, which mints a library alone with no branch and no app movement: the tag is the baseline the API floor measures the next cut against and the version the group file records. A group tag is a source ref, not a release: it matches no release or index trigger and is never recorded.
- **Every channel builds in-tree** (revised 2026-11-26). A series builds its libraries from its own `crates/`, as `main` does; the tags a cut mints are its bill of materials and the API floor's baselines, not its build input. A library fix reaches a series the way an app fix does, by cherry-pick through a pull request, and the series' group file keeps the versions the cut minted. The first cut's pinned series could not compile: cargo makes each tag a distinct source, so cross-group path dependencies inside the fetched checkouts produced four copies of `bedrock-core`, and a `[patch]` on the same repository is refused. Design D7 records the alternatives weighed.
- **App severity.** The app ignores `!`. Its only breaking signal is a `Covenant: break` trailer, and a cut targets a major for the app only when a person passes `--major`; a trailer since the last stable makes a cut without `--major` refuse and name the commits.
- **Evidence floors.** A group's bump is the greater of what its commits declare and what evidence shows: `cargo semver-checks` against each library group's last tag, measured under the stable flavor since that is the surface every series consumes, and the append-only covenant fixtures under `covenant/fixtures/<group>/` whose modification is breaking for the owning group and the app. A group with no tag yet has no baseline, so the API check skips it and says so rather than block every library pull request before the first cut.
- **One more pull-request check** joins `version-integrity`: an undeclared API break fails, and a group with no tag is skipped and says so.
- **Build data.** Each build embeds every group's version — on `main` described from the tree's tags, on a series described from the group's tag the branch descends from, so a cherry-picked fix reads as commits past it, or injected where the source carries neither — alongside `BuildInfo`, for the About surface, `--version`, and bug reports.
- **A preview bump resumes a half-finished cut** (added 2026-11-26). A series that still declares `main`'s nightly version was cut and never wrote its own; a preview bump writes its `-pre.1` and the workflow's series landing runs as for an advance. The first cut is completed this way.

## Capabilities

This change stays inside the `distribution` domain. Planner-side invariants are release planning; the pull-request checks on pins and API breaks are release integrity, the front half of distribution, not toolchain reproducibility; what the overlay's Station package builds on a series is Nix delivery.

### New Capabilities

None. `distribution/version-integrity` is created, with its purpose, by `release-groups-guards`; this change adds to it.

### Modified Capabilities

- `distribution/release-planning`: gains `ADDED` planner-side invariants — groups own disjoint paths and the app counts what it ships, read over first-parent history; library versions are minted only by a cut, on `main`, with group-scoped cuts, and a series takes a library fix by cherry-pick; a multi-group commit is a summary; the app breaks only on a covenant trailer; evidence floors each group's bump, measured under the stable flavor; builds embed every group's version; every channel builds its libraries in-tree; a preview bump resumes a half-finished cut. One published requirement is `MODIFIED`: _A dry-run transition reports its refs and renders its writes_ (from `release-dry-runs`) gains each library group's current and next version, its tag, and its manifest writes, with one scenario added. The two amendments protecting the branches require — _A series branch carries only cherry-picks of `main`_ and _The manifest version names the channel_ — were `protected-branches`'. _Release refs are minted so their pushes are observable_ stays as published and is what makes the App token mandatory for the group tags.
- `distribution/version-integrity`: one `ADDED` requirement — an undeclared API break fails the pull request. (The series-pin requirement this change carried until 2026-11-26 is withdrawn with the pins, design D8.)
- `distribution/nix-overlay`: untouched. The `MODIFIED` _Flake overlay exposes desktop packages_ this change carried — the Station built from the tag a series pins — is withdrawn with the pins (design D7); the Station builds from the evaluated tree on every ref, as published.

Two further published specs constrain this change without being touched: `distribution/release-publishing` (a channel publishes only the tag that triggered it, and withdraws only a tag it minted itself — a group tag triggers nothing and is minted by no run) and `distribution/release-index` (an entry follows its tag, and series carry no index — a group tag is never an entry). `nix-overlay`'s _A series ref builds itself_ stays as published: a series builds from its own tree, lockfiles, and recipe, as `main` does.

## Impact

- **`tooling/xtask`:** `releases::index::product_commits` becomes the group-aware first-parent walk and its `fixture::Repo` test helper grows paths, bodies, and merges; `planners::release` gains per-group plans, group-scoped cuts with floors, `--major`, the two-phase cut whose series write is the app's projection alone, a `patch` that is the app's patch bump, and the resume of a half-finished cut, with the new flags on `src/bin/xtask/tasks/release/bump.rs` and the group tags minted through `tools/github.rs`'s existing `octocrab` `create_tag`; the `version-integrity` task gains the API-break check and its workflow a `semver` job; `workflows/release.rs` and `workflows/_jobs.rs` fetch tags and inject group versions; `typegen` registers the new build-data type so the TypeScript bindings stay generated. (The series' dependency rewrite, the pin-moving `patch`, and the series-pin and single-pin checks were built on 2026-11-16 and are removed on 2026-11-26, design D7.)
- **Manifests:** `crates/bedrock`, `crates/domain`, and `crates/transload` carry the `#:tombi toml-version = "v1.0.0"` directive the Nix reader needs (`crates/outpost` and the root already carry it); `cargo-semver-checks` joins the pinned toolchain. No manifest changes shape on a series.
- **Build data:** `crates/cartograph/src/build_info.rs`, `src-tauri/build.rs`, `src-tauri/src/commands/meta.rs`, `src-tauri/src/bin/waypoints.rs`, and `distribution/nix/packages/waypoints/package.nix` (the overlay builds a fetched tag with no git metadata, so it injects the values from the group file).
- **Release pipeline:** the cut's run already opens the summary pull request, waits for its merge, and tags the merge commit; it now also tags each changed group there, cuts the series from it, and opens the series' first pull request, and `bump.yaml` carries `group`, `floor`, and `major` dispatch inputs beside `dry_run`; the nightly planner's history walk becomes first-parent too, since both planners share one walk, but its decision — did anything land — is unchanged.
- **Docs:** `docs/CONTRIBUTING.md` gains the rule that a series takes library code by cherry-pick like any code, its library versions staying what the cut minted, beside the `summary` and trailer entries `release-groups-guards` adds.

## Non-goals

- No crates.io publishing: `publish = false` stays.
- No channels for library groups; they have no installed population. A library's "release" is a tag on `main`: a version marker and a semver baseline.
- No covenant fixture coverage. The directories and the append-only rule are `release-groups-guards`'; this change applies the fixture floor at cut. A fixture per migration, payload type, ACL record, and envelope version is a follow-up change touching `bedrock`, `outpost`, and `store`.
- No versioning for components that do not ship yet; each becomes its own group when it does. The importer SDK and its plugins, which are in flight and not yet on `main`, must be named in the group file when they land, and every planner run refuses until they are.
- No change to nightly versions (`{target}-nightly.{YYYYMMDD}`, from `release-dry-runs`) or to the app's four transitions.
- No re-linting of history. The planners read older first-parent commits as `next_version` does today, dropping non-conventional subjects.
- No second source of versions beyond the group file `group-file-versions` made the declaration.
- No git dependencies on this repository, and so no credential plumbing for them (revised 2026-11-26).
- No release record or channel for `outpost` itself; the index-recorded, fetch-by-rev path stays the app's.
