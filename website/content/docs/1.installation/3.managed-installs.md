---
title: Managed installs
description: >
  Some ways of installing Waypoints leave updates to a package manager. Those copies tell you when a new version is out, but never install it themselves.
---

When a package manager owns the files Waypoints runs from, Waypoints must not rewrite them: the manager would no longer know what is installed, and its next upgrade would undo or collide with the change. Packages for those managers start the app with the `--no-self-update` flag. The flag caps the **Updates** setting at *Notify*: the app still checks for new versions and tells you when one exists, but *On* is unavailable until you install a copy the manager does not own.

Your own choice is never overwritten. If you set updates to *Off*, a managed copy stays off; if you later run the same profile from an unmanaged install, your setting comes back as you left it.

## Channels that launch this way

- **Nix** — NixOS, nix-darwin, and home-manager, through the `waypoints` overlay. The package wraps the app so every launch, from the shell or the desktop, carries the flag.
- **Arch Linux (AUR)** — joins this list when its package ships; it launches the same way.

## What you see in the app

Open **Settings → Updates**. On a managed copy, *On* is grayed out with a note that this copy is managed by a package manager, and *Off* and *Notify* remain yours to pick. **Check for Updates…** in the menu still works: it reports a newer version and leaves the installation alone.

## Updating a managed copy

Use the package manager. On Nix, update the input that provides the overlay and rebuild; on Arch, upgrade the package as you would any other.
